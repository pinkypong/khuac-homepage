## 확인한 범위

- 자동 테스트 249개 통과. 타입 검사, ESLint, diff 공백 검사 실시.
- workerd의 최신 BUILD_ID 일치 확인.
- 비로그인 HTTP 검사: 로그인/개인정보/비밀번호 복구 200, 지도/업로드/부원/관리자는 로그인으로 307, 사진 API는 401.
- 실제 로그인된 브라우저: 지도 로딩, 북한산 주말 예보 표시, 업로드 앨범 목록 및 활동 필터/검색 결과 없음 표시.
- 기존 앨범의 지도 사진 핀 6개와 썸네일 6개 로딩, 사진 확대 및 다음 사진 전환(2/6, 1600px 이미지)을 확인했다.
- 지도·날씨·앨범 확인 시 브라우저 콘솔 오류 없음.
- 사진·앨범 원본 기록을 추가·수정·삭제하지 않았다. 사진 저장과 삭제의 장애 시나리오는 mock 회귀 테스트로 검증했다.

## 공유 전에 남은 확인

- 외부 신규 계정으로 Google 가입 → 승인 대기 → 관리자 승인 → 지도 접근.
- 가입 확인·로그인 링크·비밀번호 복구 메일의 실제 수신. SMTP 설정을 이번 점검에서 확인하지 못했다. 기본 Supabase 메일 서비스는 프로젝트 팀 외 주소 발송이 제한되므로 외부 테스터의 메일 수신 확인이 필요하다.
- 실제 iPhone/Safari에서 HEIC 업로드 → 썸네일 → 원본 확인. 이번 브라우저에서는 모바일 뷰포트 변경이 적용되지 않아 데스크톱 화면만 확인했으며, 네이티브 iOS 앱도 검증하지 않았다.
- 느린 모바일 회선에서 복수 사진 업로드와 재시도. 기존 20MB 초과 HEIC는 원본 fallback만으로 모든 브라우저에서 표시된다고 보장하지 않는다.
- 신규 업로드 저장 경로가 바뀌므로 배포 후 오래 열린 업로드 화면은 새로고침한다. 이미 저장된 기존 사진은 계속 조회 가능하다.

운영 배포 전에 사용자가 로컬 수정본을 검토한다. 로컬 미리보기의 Supabase/사진용 R2 S3 연결은 기존 실제 서비스이므로 저장·삭제 시험은 합의된 테스트 기록으로 진행한다.
